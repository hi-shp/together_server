# 공지 분류와 중복 판별

## 처리 기준

분류는 활동 형식을 먼저 확인합니다. 글쓰기 특강은 교육, 한복 해커톤은 디자인 공모전으로 구분합니다. 제목의 키워드와 검증 범위에 들어온 로컬 모델이 함께 맞는 경우를 먼저 처리하고, 근거가 부족하면 제목과 기존과 같은 최대 1,000토큰 본문을 GPT에 전달합니다. 원래 게시판 이름과 분류 함수의 반환 형식은 유지합니다.

중복 검사는 연도·학기·계절·기수·회차가 명시적으로 다르면 별개로 처리합니다. 최근 10일 최대 1,000개에서 후보 3개를 찾되, 유사도 0.85만으로 공지를 버리지 않습니다. 고유 행사명과 회차가 일치하는 좁은 경우를 먼저 판정하고, 나머지는 같은 행사·변경 공지·다른 행사·자료 부족으로 구분합니다. 변경 공지와 자료 부족은 중복으로 삭제하지 않습니다. 근로·교내·학과 장학, 조교, 수강·졸업 등 학과별 모집/행정은 기존 제목 이력에 담당 학과가 없어 GPT의 추측만으로 중복 제외하지 않습니다. 이 범위는 반복 게시가 늘 수 있지만 다른 학과의 공지 누락을 우선 방지합니다.

API 기본 모델은 실제 운영 키로 호출을 확인한 `gpt-5.4-mini-2026-03-17`입니다. `GPT_CATEGORY_MODEL`, `GPT_DUPLICATE_MODEL`로 변경할 수 있습니다. 기존 `gpt-3.5-turbo`는 같은 키로 실제 대화 요청 시 404 `model_not_found`가 발생했습니다. 모델 목록 조회 성공만으로 호출 가능 여부를 판단하지 않습니다.

## 이력과 검증 범위

2026-10-26 서버 사본의 제목 31,029건과 분류 13,819건을 전부 읽었습니다. 분류 중 2,319건은 미분류·중복 표기·형식 오류 등 허용 카테고리로 사용할 수 없었습니다. 과거 분류는 정답이 아니라 기존 프로그램의 출력입니다.

학습에는 불명확한 라벨과 상충 제목을 제외한 9,942건을 사용했습니다. 같은 제목 계열이 학습·보정·시험에 나뉘지 않도록 묶었으며, 연도 제거는 분류 학습에만 적용합니다. 실제 중복 검사에서는 연도를 유지합니다. 학습 5,958건, 보정 1,988건, 시험 1,996건입니다.

제목 195건을 별도로 검토하고 학습에서 제외했습니다. 이 개발 표본에서 로컬 경로가 결정한 46건은 검토 결과와 일치했고, 불명확한 20건은 자동 결정하지 않았습니다. 규칙을 점검하며 사용한 표본이므로 전체 정확도를 뜻하지 않습니다. 검토 역시 독립된 사람의 정답 검수가 아닌 제목 기반 검토입니다. 과거 라벨과의 98% 일치율 등을 실제 정확도로 해석하지 않습니다.

실제 API로 어려운 분류 24건과 중복 쌍 12건을 비교한 뒤, 수정 프롬프트를 일부 사례에 재검사했습니다. 소규모 개발 검사이며 운영 정확도·호출 절감률은 아직 측정하지 않았습니다. API 장애나 잘못된 응답 형식은 예외로 처리해 기존 실행기의 재시도 경로를 유지합니다.

연도·회차가 다른 이력 쌍이 모두 기존 코드의 오판 사례인 것은 아닙니다. 기존 검사에도 최근 10일 제한이 있었습니다. 초기 API 개발 검사의 과거 0.85 판정은 시간창을 제외한 제목 규칙 비교였으며, 실제 운영 오판율로 사용하지 않습니다. 현재 비교 도구는 시간창과 원래 제목 정리 방향을 반영하지만, 공지 쌍 단위 비교이며 과거 전체 후보 1,000개의 처리 순서를 재현하는 검사는 아닙니다.

모델은 `.runtime/intelligence/category-model.json.gz`에 별도로 둡니다. 모델이 없거나 호환되지 않으면 본문 분류로 넘어갑니다. 운영 추론은 Python 기본 라이브러리를 사용하며, 분석용 패키지를 운영 서버에 설치하지 않습니다.

## 대표 원문 비교

`NOTICE_INTELLIGENCE_MODE=shadow`이면 이미 받은 HTML에서 원문 주소·부서·첨부 링크·명시된 게시일과 본문 일부를 별도로 기록합니다. 추가 다운로드나 게시 요청은 없습니다. 최대 1만 건, DB 약 128 MiB로 제한하며 기록 실패는 게시를 중단시키지 않습니다.

같은 순회에서 확인된 최대 200개 후보에 대해 회차가 같은 것끼리 비교하고, 일정·대상·신청 방법·첨부 유무·본문 정보량을 기준으로 대표 후보를 기록합니다. 관련 부서와 원문 주소도 함께 남깁니다. 결과는 `.runtime/intelligence/last-cycle-proposal.json`입니다. 이 파일은 제안일 뿐 실제 게시 순서·알림 대상·기존 게시물을 바꾸지 않습니다.

과거 제목 파일에는 원문 주소·본문·첨부파일·원래 게시일이 없습니다. 저장 시각은 원래 게시일과 다릅니다. 과거 이력만으로 어느 원문이 더 충실했는지 확인할 수 없습니다.

## 게시 후 보강

`NOTICE_ENRICHMENT_MODE=enabled`이면 이후 직접 게시하고 제목·원문 주소·게시 주소를 대조해 등록한 공지만 보강합니다. 예전 게시물 전체를 제목 검색으로 찾아 수정하지 않습니다. `published-posts.json`에 최근 대상 최대 1,000건을 14일 범위로 보관합니다. 파일은 최대 16 MiB입니다.

같은 행사라는 근거가 충분하고 정보가 늘어나는 경우에만 처리합니다. 서로 다른 연도·회차·마감, 담당 학과가 불명확한 경우와 대상 게시물이 둘 이상인 경우는 자동 선택하지 않습니다. 한 글의 보강은 최대 3회입니다.

- 제목의 연도·회차·새 공지 표시와 필요한 학과 표기를 유지합니다.
- 표·사진·누락된 본문이 추가되거나 깨진 글자가 뚜렷하게 개선되면 더 충실한 원문 하나로 본문을 교체합니다. 일정·인원·연락처와 기존 표·사진을 함께 대조합니다.
- 표현이나 파일 주소만 달라진 경우에는 본문을 유지합니다. 새 첨부파일만 있으면 파일을 추가하고 제목과 본문은 그대로 둡니다.
- 기존 첨부파일을 보존합니다. 같은 내용의 파일은 다시 올리지 않고, 같은 이름의 다른 파일은 해시를 붙여 이름을 분리합니다.
- 저장 전 제목·본문·파일 해시가 등록 당시와 다르면 수동 수정으로 보고 자동 수정에서 제외합니다. 새 공지 게시가 필요한지는 기존 중복 판별 흐름으로 처리합니다.
- 수정 전 본문과 원본 파일을 제한된 권한으로 백업하고, 저장 후 제목·본문·모든 파일 해시를 다시 확인합니다. 검증에 실패하면 백업으로 복원을 시도하며, 확인되지 않은 저장을 반복 전송하지 않습니다.
- 첨부는 기존 파일을 포함해 최대 10개, 한 작업의 검증 파일 합계 32 MiB, 본문 300 KB로 제한합니다. 수정 백업은 약 128 MiB 범위에서 확인된 오래된 작업부터 정리하며, 미확인 백업이 차면 추가 수정을 중단합니다.

2026-10-26 실제 게시물 한 개에서 제목·본문 수정과 파일 추가 후 재조회·다운로드 해시 검사를 통과했습니다. 기존 파일 2개를 보존한 채 테스트 파일을 추가해 3개로 저장한 뒤, 테스트 문구와 파일을 제거하고 원래 제목·본문·파일 해시로 복원했습니다. 한글·영어 화면 모두에서 사용할 수 있도록 버튼 문구 대신 파일 관리 영역을 찾고 비동기 목록 갱신을 기다립니다.

보강 자체는 별도 쪽지·이메일 전송 함수를 호출하지 않습니다. 수집 순회의 기존 학과별 알림 처리는 유지합니다. 크롤러를 시작하면 실제 게시·보강·알림이 수행됩니다.

## 재현

원본 CSV/TXT는 수정하지 않고 출력 경로를 별도로 지정합니다.

```bash
python3 tools/analyze_history.py --help
python3 tools/find_event_pairs.py --help
python3 -m pip install -r requirements-analysis.txt  # 분석 컴퓨터에서만 실행
python3 tools/train_title_model.py --help
python3 tools/evaluate_local_router.py --help
python3 tools/evaluate_ai_decisions.py --help  # 실제 API 사용, 호출 상한 적용
python3 -m unittest discover -s tests -v
```

모델 학습만으로 적용 승인이 나지 않습니다. 별도 검토 파일의 해시와 제외 조건을 확인한 후 `evaluate_local_router.py`로 로컬 경로의 적용 범위를 검사합니다. API 비교 도구는 `--baseline-ref`로 지정한 과거 커밋을 읽어 비교합니다. 원문·계정·신청자 데이터는 커밋하지 않습니다.

`NOTICE_CLASSIFIER_MODE=legacy`는 기존 키워드 순서, `NOTICE_DUPLICATE_MODE=legacy`는 기존 0.85 즉시 판정을 사용합니다. API 어댑터의 모델과 프롬프트는 현재 버전을 사용합니다. 과거 코드는 보존된 커밋과 legacy 브랜치에서 확인할 수 있습니다.
