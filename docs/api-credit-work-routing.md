# API 잔액 사용 후 로컬·Work 판단으로 전환

2026-11-24 운영자 지시를 적용한 선택형 정책이다. `.runtime/decision-provider.json`의
`policy`가 `api_credit_then_work`일 때만 사용하며, 기존 프로그램의 기본 동작은 유지한다.

## 판단 순서

1. 기존 실제 API 응답 캐시를 먼저 재사용한다.
2. 승인된 남은 API 크레딧이 있는 동안 기존 API로 판단하고 로컬 예측도 보존한다.
3. 실제 `insufficient_quota`/`credit_balance_exhausted` 응답 또는 승인 잔액이 한 요청의
   보수적인 최대 비용보다 작으면 전환 상태를 영구 기록한다. 재시작으로 API를 다시
   호출하거나 새 잔액을 자동 배정하지 않는다.
4. 전환 후에는 확신이 높은 로컬 판단을 사용한다. 확신이 낮거나 원문·대상·회차 근거가
   부족한 판단은 ChatGPT 계정으로 로그인한 Codex CLI에서 검토한다.
5. Work도 응답하지 않으면 기존 로컬 대체·사후 재검토 원장을 사용한다. 저장·발송 여부가
   불확실한 작업을 다시 요청하는 권한은 생기지 않는다. 실제 대표 게시글 확인과 수동 수정
   보호도 유지한다.

일일 API 한도는 도입하지 않는다. 이전의 5달러 보존 조건은 이 운영 정책에서 해제한다.
잔액 계산에는 기존 실제 사용량·소액 미정산 예약·만료일이 다른 크레딧을 반영한다.
새 결제·자동 충전·추가 학습 예산을 설정하지 않는다. 확인하지 못한 유료 결과를 삭제하거나
재접수하지 않으며, 알려진 요청 가격이나 비용 증거가 없을 때는 Work로 우회한다.
프로그램이 계산한 잔액은 결제 화면의 실측 잔액과 구분한다.

## Work 사용량 절약과 기록

- 이미 사용하던 제목·본문 발췌·중요 행사 필드·한 후보씩 비교하는 입력을 재사용한다.
- 긴 운영 채팅, 계정 정보, 수신자 목록, API 키를 전달하지 않는다.
- 공지 판단 전용의 짧은 기본 지시와 고정 실행 문맥을 사용해 공통 입력 캐시를 재사용하기 쉽게 한다.
- 별도 로그인 저장소와 도구 없는 읽기 전용 실행을 사용한다. API 키 인증은 강제로 제외한다.
- 응답 캐시는 분류 7일·중복 30일 유지하며 실제 API 캐시와 분리한다.
- 정상 수집 순서와 첫 중복에서 비교를 멈추는 동작은 유지한다. 이미 사후 검토 대기 중인
  건만 최대 8개씩 묶고 공통 판단 지시를 한 번 전달한다. 빈 대기열은 호출하지 않는다.
- 원격 판단 한 건이 55초를 넘으면 해당 요청을 미확정으로 보존한다. 이는 전체 크롤링
  사이클 시간 제한이 아니다. 실패 후 10분 동안 새 원격 재시도를 쉬며 로컬 수집은 계속한다.
- 실제 실행 횟수·입력·출력·캐시 토큰·미확정 상태를 `.runtime/work-codex/decisions.sqlite3`에
  기록한다. Work 판단의 출처를 비교 원장에 따로 보존하며 사람 정답으로 표현하지 않는다.

Work는 공식 Codex `exec`와 ChatGPT 계정 로그인을 사용한다. 포함 구독 사용량과 다른 Work
작업의 사용량은 공유한다. 포함량을 다 사용하면 실제 계정 상태에 따라 응답이 제한될 수 있으며,
이때 별도 API 유료 호출로 되돌아가지 않는다. 운영 모델을 자동 교체하지 않는다.
