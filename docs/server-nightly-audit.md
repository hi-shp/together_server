# 서버 평일 일일 점검

한국시간 월~금 오후 10시에 `together-nightly-audit.timer`가 실행한다. 토·일에는 새 점검을 시작하지 않는다. PC나 ChatGPT 앱 예약이 없어도 서버에서 실행한다. 공휴일이어도 월~금이면 실행한다.

그날 처음 발견한 원문이 없으면 무거운 조회와 Work 호출을 생략한다. 성공적으로 게시한 글만 세지 않고, 아직 게시하지 못한 새 원문도 활동에 포함한다. 반복 관측과 예전 글의 재확인은 새 글로 세지 않는다. 활동 자료가 없으면 0건으로 단정하지 않는다.

## 검사 범위

- 보존한 신규 수집·분류·중복·게시·보강·첨부·발송·Discord 사건을 해당 기간 전체에서 대조한다. 독립 사건 원장과 순환 로그의 겹친 사건은 다중집합으로 합친다.
- 전체 공식 기관·교수 홈페이지 목록과 공개 메뉴를 다시 조회한다. 등록된 공지 URL은 운영 파서로 검사하며, 학생지원시스템 두 게시판은 로그인·목록·본문·문서 첨부 정보를 읽는다. 중단·삭제 메뉴는 정상 목록과 구분하고 재등장 후보를 보존한다.
- 실제 게시글·대표 원문·제목·본문·첨부 해시·기존 별표 제거 검색의 모든 페이지를 대조한다. 최근 실제 별도 게시글의 추가 중복 후보도 점검한다.
- 학교 쪽지 전체 대화·개별 발신·전체 수신자와 이메일 전체 연결 페이지를 전송 의도·시도·영수증과 대조한다. 외부 받은편지함 수신을 확인했다고 표현하지 않는다.
- 알려진 모든 Discord 전송 ID와 전체 로그 첨부를 조회하고 실제 파일 해시를 비교한다. 알 수 없는 채널 이력과 과거 ID 보존 공백은 계속 미확인으로 남긴다.
- 크롤러·이메일 작업자·야간 대기·디스크·inode·메모리·열린 삭제 파일·임시 파일·실패 반복·API 원장·크레딧 만료·그림 첨부 제외·모델 비교 자료를 확인한다.
- 분류·중복의 운영 입력과 실제 분류 결과를 Work로 별도 검토한다. 기존 API 결과와의 일치율을 사람 정답률로 표현하지 않는다. 불일치와 자료 부족은 별도 확인 대상으로 보존한다.

## 기능을 바꾸지 않는 실행 방식

수집기, 분류·중복 알고리즘, 모델, 게시·보강·쪽지·메일 순서와 CSV/TXT 기록 시점은 변경하지 않는다. 점검은 별도 프로세스에서 읽기 전용으로 실행한다. 미확인 저장·발송은 재요청하지 않으며 점검을 위한 시험 게시·발송을 하지 않는다. 기존 12시간 이메일 정책은 운영 작업자가 그대로 수행한다.

Work 점검에는 별도 실행 잠금·응답 캐시·시도 원장을 사용한다. 운영 판단의 Work 잠금을 점검이 잡아 로컬 대체를 유발하지 않는다. 인증 저장소만 기존 ChatGPT 로그인과 공유하며 API 키는 전달하지 않는다. 점검은 API 유료 요청으로 우회하지 않는다.

짧은 기존 판단 입력과 동일한 규칙, 실제 원문·대상·연도·학기·회차·마감 근거를 유지한다. 동일 입력은 응답 캐시로 재사용한다. 각 공지의 최종 분류와 중복으로 생략한 판단은 검토한다. 서로 다른 공지라는 운영 결과와 높은 확신의 로컬 결과가 일치하는 명백한 비일치 후보는 기계 대조에 포함하되 Work에 다시 보내지 않는다. 실제 별도 게시글 사이의 유사 후보는 따로 검토한다. 운영의 기존 최대8건·55초 응답창은 유지한다. 별도 일일 점검만 최대16건·약96KiB 입력 묶음과 120초 응답창을 사용하며 긴 채팅이나 정상 로그 전체를 모델에 보내지 않는다. Work가 응답하지 않으면 미완료 상태와 실제 시도를 보존한다.

같은 회차의 공식 메뉴 조사에서 이미 받은 정상 HTML은 정확한 원본 바이트와 인코딩을 재사용해 운영 파서로 검사한다. 오류·이동 미확정 응답·6시간이 지난 캐시는 재사용하지 않는다. 어제의 캐시를 오늘 접속 확인으로 세지 않는다. 저우선순위·CPU 35%·메모리 384MiB로 점검 자원만 제한하며 크롤러의 사이클 제한을 추가하지 않는다.

## 중단·누락·중복 대응

- 실행 잠금과 예정 시각으로 같은 회차의 중복 실행을 막는다. 중단 뒤에는 완료한 단계·확인한 파일을 재사용한다.
- 항목별 검증 위치는 실제 확인이 끝난 항목만 갱신한다. 미확인 범위, 주말 기록, 밤 10시 이후의 기록은 다음 활동 있는 평일에 이어서 검사한다.
- 서버가 꺼져 예정 시각을 놓치면 다음 평일에 놓친 평일 회차를 확인한다. 주말 재부팅으로 새 검사를 시작하지 않는다.
- 학교 접속 실패·빈 본문·삭제 메뉴·구조 변경·학교 측 중단을 정상 0건으로 바꾸지 않는다. 확인하지 못한 새 주소는 후보로 남기고 구독명·기준 번호를 임의 변경하지 않는다.
- Work 불일치만으로 대표글을 삭제하거나 과거 공지를 다시 게시·발송하지 않는다. 실제 원문·게시·첨부·수신자 근거와 함께 다음 검증에서 이어서 확인한다.
- 정상·사소한 변화는 보고서 파일에만 남긴다. 실제 학교 전체 수신자·본문을 대조해 확인한 쪽지 중복 같은 큰 문제만 기존 운영 Discord로 한 번 알리며, 24시간 중복 방지 기록을 먼저 저장한다. 기존 건강 감시는 계속 실행한다. 정기 비용·잔액 추세로 메일을 보내지 않는다.

결과는 `.runtime/nightly-audit/runs/예정시각/점검결과.md`, 기계 대조 증거는 같은 폴더에 저장한다. `.runtime/nightly-audit/state.json`은 항목별 검증 위치, `latest.json`은 마지막 실행 위치이다. 실제 수신자·쿠키·원문 양식은 서버의 비공개 파일에만 둔다. Git에는 넣지 않는다.

확인 명령은 `systemctl list-timers together-nightly-audit.timer`, 읽기 전용 실행 계획은 `python3 tools/nightly_audit.py --plan`이다. `--run-now`는 별도의 평일 즉시 검증이며 그날 오후 10시 회차를 소비하지 않는다.

## 적용하지 않은 최적화

대학공지 갱신 전후의 CSV 재로드를 합치거나 title/yesterday 기록을 앞당기지 않는다. 이메일·쪽지·첨부 글을 병렬 저장하거나 첨부 없는 글부터 게시하지 않는다. 원격 저장·발송을 확인하는 요청도 생략하지 않는다. 이런 변경은 순서와 재시도 의미가 달라질 수 있어 적용하지 않았다. 성능 개선은 점검의 증분 범위, 동일 입력의 캐시·묶음, 같은 회차 HTML 재사용, 연결 재사용과 별도 저우선순위 실행에 한정했다.

학교 메일 표시는 오전·오후 표기 없는 12시간제로 확인했다. 실제 영수증·제목·전체 수신자가 일치한 요청 시각과 인접 전송 ID를 근거로 오전/오후를 대조한다. 경계에서 어느 시간인지 정해지지 않으면 미확인으로 보존한다. Work 입력의 body/body_text/body_excerpt가 완전히 같은 경우에만 중복 사본을 없애고, 내용이 다르면 모두 남긴다.

기존 건강 감시도 확인 대기와 장애를 구분한다. 원래 실제 이메일 시도 기록이 있고 12시간 이내인 미확정 건은 대기 수로 보존하며 그 건만으로 발송 장애·정체를 경고하지 않는다. 실제 미처리 후속 메일, 작업자 중지, 쪽지 미확정과 12시간을 넘긴 이메일은 계속 점검한다. API→Work 정책·인증/실행 파일과 최근 실제 Work 성공이 모두 확인될 때만 예정된 API 잔액 소진·만료 경고를 생략하며, 계정/키/모델 오류와 Work 실패·연결 미확인은 경고에서 제외하지 않는다. 이 구분은 감시 결과만 바꾸며 실제 발송·재시도·API 지출 정책에는 영향을 주지 않는다.

실제 별도 게시글 사이의 추가 중복 검토 범위는 원문의 최초 관측 시각보다 실제 게시 영수증의 갱신 시각을 우선한다. 이전에 수집했지만 늦게 게시한 글도 다음 검토에서 빠지지 않으며, 기준 시각 뒤에 게시한 글은 다음 구간으로 넘긴다. 같은 행사의 전달 간격은 두 원문의 관측 시각 차이로 대조하되 게시 순서가 뒤바뀌어도 비교한다. 이 규칙은 읽기 전용 점검의 범위만 보완하며 운영 중복·분류·게시 순서는 그대로다.
